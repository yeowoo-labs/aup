# PSA-2026-010 — 긴 연산 사슬이 컴파일러의 스택을 다 써서 빌드가 죽음

- 공개: 2026-11-02
- 심각도: 중간. 가용성. 문법에 맞는 소스 하나가 `aup check`·`build`·`query`·`watch`를 SIGSEGV로 끝냈다. 괄호 없이 이은 연산이
  8 MiB 스택에서 12,000항쯤이면 넘쳤다. ASan은 스택 넘침으로만 보고했고 메모리 오염은 찾지 못했다. 남이 준 소스를 짓는 곳
  (생성기의 출력을 짓는 빌드, 받은 질의를 짓는 도구, 편집기의 watch)에서 빌드를 멈출 수 있다. 실행 중인 Pure는 aup를 부르지 않으므로
  닿지 않는다.
- 영향을 받는 판: 3e35975(2026-09-25, 첫 컴파일러)부터 6e16248 앞까지
- 고친 커밋: 6e16248

## 무엇이었나

식의 중첩은 64로 막혀 있었지만, 그 한도는 파서 자신의 재귀를 셌다. `a + a + …`, `r.x.x…`, `d[0][0]…`처럼 이어 쓴 사슬은 파서가
고리 하나로 만들지만 트리는 사슬 길이만큼 깊어진다. 파서 뒤의 단계(타입 검사와 방출)는 그 트리를 재귀로 내려간다. 레코드 값 안의
레코드 값과 send 그룹 안의 그룹은 파서 자신의 재귀였는데도 세지 않았다.

## 고침

식의 중첩을 트리의 높이로 센다. 노드가 제 높이를 지니고, 파서가 트리를 만드는 곳(사슬의 고리마다, 끝난 식·레코드 값·send 그룹마다)에서
잰다. 64를 넘는 트리는 넘긴 고리에서 괄호와 같은 진단(`expression nesting exceeds 64`)으로 거부한다. 레코드 값과 send 그룹도 파서의
중첩에 센다. 64항까지의 사슬은 전처럼 지어지고, aup·Pure·Vega의 모든 소스(76개 모듈)가 전과 같은 바이트를 낸다.

## 회귀 시험

`tests/check.py`의 진단 열 개(65항과 100,000항의 `+` 사슬, `==` 사슬, 처리기·let·fn 안의 사슬, 필드 사슬, 위치 사슬, 겹친 레코드 값,
겹친 send 그룹)와 `nesting`(100,000항을 check·build·query·watch가 같은 진단으로 거부하고 모듈을 쓰지 않는지, 64항이 지어져 Pure에서
도는지). 고치기 전에는 SIGSEGV로 끝나 실패한다.
